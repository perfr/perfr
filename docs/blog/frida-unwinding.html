Fixing sampled stacks without losing call timings

The return-address problem is fixed on Linux x86-64. Timing hooks keep measuring complete calls. Before unwinding a sample, perfr restores the real return addresses in its copy of the stack.

1. Why stack unwinding broke

To measure when a function finishes, Frida Gum replaces its return address with the address of its own return handler. Gum remembers the real caller privately and sends execution there after recording the exit. The program still returns correctly.

But perf samples the stack with that replacement address. The external unwinder sees Gum’s generated code instead of the caller, and cannot reliably continue. The real address in Gum’s private bookkeeping is absent from the sample.

2. How the fix works

On entry, the agent records the thread, return-slot address, original caller, verified Gum trampoline, and time. On exit, it closes that invocation’s lifetime. This history travels separately from the existing timing events.

Each recursive invocation gets its own record. Completed calls remain available until older samples have been processed. Checking the slot’s current value prevents an abandoned call’s record from overwriting an ordinary address after stack reuse.

3. What proves it works?

The live fixture uses two threads, different callers, four recursive levels, and an optimized binary without frame pointers. Both recursive and leaf functions have timing hooks. The test checks caller chains and all 480 positive call durations, including parent/child nesting, in the same capture.

A separate restart test holds two calls across Stop and Start: 72 samples correctly remain partial because their entries preceded the new recording; 210 subsequent samples recover full chains. Unit tests also exercise concurrent publication, delayed samples, reused slots, tail-call return chains, and journal overflow.

4. How reliable is the fix?

It restores verified addresses; it does not guess them. Missing invocation history stops unwinding at a known trampoline. Lost metadata, an unsupported redirect, or a stalled publisher disables repair and keeps samples leaf-only, with a visible status message. Timing events continue.

The tradeoff is extra entry/exit bookkeeping and bounded memory for return history; its overhead has not yet been benchmarked across real workloads. This implementation covers Linux x86-64. It does not supply missing unwind rules for samples taken inside relocated instructions or hook machinery, fix another tool’s hooks, or establish that C++ exceptions can safely cross Gum hooks.

Reproduce the test and inspect the implementation

From this worktree, build matching service, helper, and native agent, then run the live regression. Sampling and attach permissions must already work; the test does not change them. Its Python environment needs pyarrow.

cargo build -p perfr -p perfr-hook -p perfr-lib --features perfr-lib/native
cc -O2 -g -fomit-frame-pointer -fno-optimize-sibling-calls -pthread   tools/e2e/frida_unwind_target.c -o /tmp/perfr-unwind-target
python tools/e2e/frida_unwind.py   --service target/debug/perfr --helper target/debug/perfr-hook   --agent target/debug/libperfr.so --target /tmp/perfr-unwind-target   --out /tmp/perfr-unwind-results

crates/perfr-lib/src/gum.c records return interception; crates/perfr-frida-transport/src/returns.rs carries its history; crates/perfr/src/frida_returns.rs repairs copied slots; crates/perfr-unwind/src/unwinder.rs stops at unresolved trampolines.

The service waits for committed metadata before consuming samples. The journal holds 16,384 records, retained invocation history is capped at 262,144 entries, and a publisher stalled for 250 ms invalidates repair. Known trampoline addresses survive capture transitions so older in-flight calls cannot silently acquire guessed callers. This is conservative: unsupported or missing history can shorten stacks.

Mechanism verified against pinned Frida Gum 17.17.0. Trampoline identity is checked using Gum’s public invocation-stack translation API. Results are local test observations, not a guarantee for all binaries.
